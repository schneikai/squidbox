# Plan: a library belongs to an owner (one database and one file set per library)

**Status: proposed.** Verified against the code on 2026-10-15 at `3dde120`. Baseline: `npx vitest run` in `apps/mobile` is green (156 tests, 5 skipped without Postgres), in `apps/server` 50 tests (17 skipped). The paged-reads refactor (`docs/paged-reads-plan.md`) is the style and level of detail this plan follows.

Goal, decided by the owner: the app keeps one SQLite database and one set of file folders per **library**, and a library belongs to an **owner**: "This iPhone" (local-only) or account `U` on server `S`. One library is open at a time. Sync runs only for an account library with a valid session. Nothing is wiped as a side effect of signing in or out; removing a library is an explicit, counted action. The model makes a local-only mode (Apple HIG "Managing accounts", App Review 5.1.1(v)) possible; §5 says what of it is in scope now. Criteria as before: SIMPLE, ROBUST, CLEAN, DRY, fixed at the root.

## 0. Diagnosis (what the code does today)

- **One store.** `sync/db/client.ts` opens `squidbox.db` once (`openDatabase`, module singletons `db`/`opening`, never closed); `DatabaseGate` in `App.js` opens it and `MigrationGate` runs `useMigrations(getDb(), migrations)`. 21 files call `getDb()` (33 call sites): the providers (`AssetsProvider`, `AlbumsProvider`, `PostsProvider`), `useLiveQuery` → `watchQuery(getDb(), …)`, `useSyncStatus`, `useInspector`, `useRecordCounts`, `useSeedOrClose`, `AssetScreen`, `CreatePostScreen`, `Album.jsx`, `DeletedAssetsAlbum`, `SortableAssetGrid`, `useAssetSelectionActions`, `AssetPickerProvider`, `RandomSuggestionsModal`, `AiChatModal`, `useResortAlbumsByName`, `CloudSyncProvider`, and `worker.ts` (dynamic import). All of them resolve the database at call time, nothing caches a reference across calls; only a live watch holds one for its lifetime (stopped on unmount) and a sync run for its duration (single-flight). That is what makes a switch mechanical.
- **One file set.** `utils/assets/files/constants.js` (`${documentDirectory}assetfiles/`) and `utils/assets/thumbnails/constants.js` (`…assetthumbnails/`), read by `getAssetFileUri`, `assetFileExistsAsync`, `deleteAssetFileAsync`, `createAssetFileDirectory`, `getAssetThumbnailUri`, `hasThumbnailAsync`, `createAssetThumbnailDirectory`, `deleteAssetThumbnailAsync`; consumers are `buildAssetAsync`, `createAssetThumbnail`, `uploadAssetFileAsync`, `uploadAssetThumbnailAsync`, `preloadAssetThumbnailsAsync`, `useSaveAssetsToMediaLibrary`, `AssetImage`, `CloudSyncProvider` (deletes the file after its upload). On web the `.web.js` variants keep presigned URLs in the global `webThumbnailUrls` map (`documentDirectory` is null on web). The downloads cache (`cacheDirectory/downloads`, `downloadAssetFileAsync`) is transient and stays global.
- **Signing in as another user wipes everything.** `CloudProvider.startSessionAsync` runs `resetSyncForUser(db, user.id)` inside `withSyncPaused`; a different `lastSyncUserId` (`sync_meta`) runs `resetLocalSync`, which deletes every collection table, the outbox, the cursor and the first-sync flag, unsynced work included, after `confirmLoginAsync`'s generic warning. `lastSyncUserId === null` records the new user without a wipe, so an unknown owner's data is adopted silently. Files are never touched: A's `assetfiles/` stay on disk under B (the orphaned-files issue). `confirmLogoutAsync` says "All data on this device is removed" while `endSessionAsync` only clears the stored user (the comment in `CloudProvider` says the library is kept on purpose).
- **Sessions aren't bound to a server.** `apiTokenStore(.web).js` keeps two keys (`accessToken`, `refreshToken`) with no server or user; `API_BASE_URL` (`apiBaseUrl.js`) is the env URL or, under `dev:local`, the dev server's origin, whose tunnel host changes per run. `loginAsync` and `refreshAccessTokenAsync` write the access token, then the refresh token (a crash between the two leaves a token pair the server will reject at the next refresh). `logoutAsync` posts through `apiWithAuthentication`, which attaches a bearer the route doesn't check: `/auth/logout` has no `preHandler`, so the "refresh rotates the token, then logout revokes the stale one" failure the brief describes cannot happen on today's code (the route never answers 401). It would the day the route gets one, and the bearer is noise, so the plan still moves it to plain `api`. `initializeCloudAsync.handleMissingUser` clears the tokens on any error, a network error included. A rejected refresh ends the session (`notifySessionExpired` → `endSessionAsync` + "Signed out" alert).
- **A backup run outlives a session change.** `CloudSyncProvider.syncAssets` loops over `readUnsyncedIds`; each `uploadFileAsync` reads whatever access token is stored at that moment and refreshes whatever refresh token is stored on a 401. After a switch it uploads A's file with B's token into B's storage, marks A's record and deletes A's local copy; a failure writes `syncError`. `useBackupCounts` reports zeros while `!isAuthenticated`, and `SettingsScreen` shows nothing but the login form when signed out (todo: "Uploads during an account switch").
- **Server.** `authenticate` verifies the JWT and sets `request.userId` without a user lookup; the storage routes look the user up themselves (`storageFor` → 401), the sync routes don't (an unknown user id hits the FK and answers 500). `rotateRefreshToken` deletes the presented token in the same transaction: a refresh whose response is lost (timeout after the server committed) leaves the client with a token the server no longer knows, and the next refresh signs it out. Nothing identifies a server: `/up` returns `{ status: 'ok' }`.
- **Other device state.** AsyncStorage: `user` (`features/cloud/user/*`), `app-settings`, the AI keys of `aiSuggestionsStorage.js` (`ai_suggestions_chat`, `_model`, `_default_prompt`, `_system_prompt`, `_variation_prompt`, `_random_tweets_prompt`). Sentry: `Sentry.init` in `App.js`, `captureException` in `BootErrorBoundary`, `AppInit` and the thumbnail loader; no user scope. Tests: `accountSwitch.test.ts` pins today's wipe; `refreshAccessToken.test.ts` mocks the two-key store; server `tokens.test.ts`, `routes.auth.test.ts`, `health.test.ts`. The web preview (`scripts/webPreview.mjs`) logs in over HTTP and writes the two localStorage keys before the page loads.
- **expo-sqlite 55.0.20, same API on both platforms.** `openDatabaseAsync(name)`, `closeAsync()`, `deleteDatabaseAsync(name)`. Both platforms hand out one shared native handle per path unless `useNewConnection` (`findCachedDatabase` in `web/worker.ts` and `ios/SQLiteModule.swift`), and closing one handle closes it for every holder; iOS `deleteDatabase` throws while the database is open or when the file is missing. Web runs wa-sqlite on an `AccessHandlePoolVFS` with 6 pooled OPFS handles (one open database costs two: the file and its rollback journal); the `directory` argument is unsupported on web, so names stay flat. drizzle's `migrate` keeps `__drizzle_migrations` per database, so each library migrates itself.

## 1. The model

### 1.1 Owner, library, registry

```ts
type Owner = { kind: 'device' } | { kind: 'account'; serverId: string | null; userId: string; email: string };

interface Library {
  id: string;                 // registry key; names the db and folders of libraries created after the migration
  owner: Owner;
  dbName: string;             // 'squidbox.db' for the migrated library, `library-${id}.db` otherwise
  filesDir: string;           // relative to documentDirectory: 'assetfiles/' | `libraries/${id}/files/`
  thumbnailsDir: string;      // 'assetthumbnails/' | `libraries/${id}/thumbnails/`
  createdAt: number;
  lastOpenedAt: number;
  closed?: { pendingCount: number; unsyncedCount: number; bytes: number; at: number }; // taken when it closed
}
```

The **registry** is one JSON document in AsyncStorage (`libraries`: `{ libraries: Library[], openId: string }`), written whole, so every change is one atomic `setItem` on both platforms. It is the only place that knows where a library lives: nothing derives paths from an owner, and the migrated library keeps today's names, so the migration moves nothing (§1.6). The counts and size of a closed library can't change, so the snapshot taken at close is exact; the open library's counts come live from its database (`useSyncStatus`, `useBackupCounts`). `serverId: null` is only the migrated library before its first `/me` or login resolves it (§1.6). Account libraries are keyed by `(serverId, userId)`, never by URL (§1.3). There is at most one device library; it is created on demand (`deviceLibrary()`), never deleted by the app in this plan.

Everything in SQLite is per library: the collections, the outbox, `sync_meta` (cursor, status, `firstSyncDone`, `sync_log`) and the Inspector that reads them. `lastSyncUserId` retires: the owner lives in the registry (`getLastSyncUser`/`setLastSyncUser` go in step 3). Per library on disk: `filesDir`, `thumbnailsDir`; per library in memory: the `webThumbnailUrls` map (cleared on a switch) and the thumbnail loader's queue (remounted). **Global**: the registry, the session (§1.3), `app-settings`, the AI model, prompts and chat history (a scratch conversation, not library content; see §6), Sentry (unchanged; a `library` tag is not worth a step), the downloads cache.

### 1.2 Module layout

```
src/library/registry.ts        read/write the registry; findAccountLibrary(serverId, userId), deviceLibrary(), add/update/remove
src/library/migrateInstall.ts  one-time: turn today's squidbox.db + folders into the first registry entry (§1.6)
src/library/current.ts         openLibrary(id), closeLibrary(), getLibrary(): the open library (what getDb() is to the db)
src/library/switchLibrary.ts   the switch, inside withSyncPaused (§1.4)
src/library/removeLibrary.ts   delete db + folders + registry entry (§1.5 (b), (c))
src/library/mergeLibrary.ts    copy one library into another (§1.5 (f), (g))
src/library/libraryLabel.js    'This iPhone' / 'This iPad' / 'This device' / the email
src/library/LibraryProvider.js useLibrary(): { library, libraries, switchLibrary, removeLibrary } for screens
src/utils/cloud-api/sessionStore(.web).js  the one session record (§1.3), replaces apiTokenStore
src/sync/backupRun.ts          the upload loop, out of CloudSyncProvider (§1.7)
```

`src/library` is TypeScript and joins `tsconfig.synccheck.json`'s `include`. Like the sync engine, `registry`, `current`, `switchLibrary`, `removeLibrary` and `mergeLibrary` take their platform through one injected object (`platform: { openDb(name): Promise<AppDb>; deleteDb(name); fs: { exists, makeDir, move, remove, size } ; storage: { get, set } }`), bound once to expo-sqlite, expo-file-system and AsyncStorage in `src/library/platform.ts`; the tests bind `makeTestDb()` per name, an in-memory fs and a Map. That is the same DI the worker uses (db + transport) and is what keeps `test/accountSwitch.test.ts` a node test.

`sync/db/client.ts` keeps `getDb()` and gains `openDatabase(dbName)` / `closeDatabase()`: open runs `PRAGMA cache_size` and drizzle's `migrate(db, migrations)` (`drizzle-orm/expo-sqlite/migrator`, the function behind today's `useMigrations`, which already runs on the sqlite-proxy db), so a library is migrated before anything reads it and `MigrationGate` goes; close is a queued unit of the driver (`AppDb.close()`: waits for the queue, closes the connection, and every statement queued after it rejects with "The database is closed"). The 33 `getDb()` call sites keep their one-liner: it returns the open library's database. The file helpers read `getLibrary().filesDir` / `.thumbnailsDir` instead of the two constants (`${documentDirectory}${dir}${filename}`); the constants files and `createAssetFileDirectory` / `createAssetThumbnailDirectory` stay as the single place that makes a directory, now for the open library.

### 1.3 Session and server identity

One **session** record, `{ serverId, userId, email, apiBaseUrl, accessToken, refreshToken }`, stored as one JSON value under `session` in SecureStore (native, `AFTER_FIRST_UNLOCK` as today) and localStorage (web). One write per change, so a refresh persists both tokens atomically (Phase-1 "persist the refresh token first, or both atomically": both). There is one session at a time, the open account library's; a parked library has none and re-signing into it asks for the password (§6, decision 7). `isAuthenticated` = the session's `(serverId, userId)` equals the open library's owner and the session is verified for `API_BASE_URL` (below). `needsReauth` = the open library is an account library and `!isAuthenticated`.

The server reports a stable **`serverId`** (`SERVER_ID` in its config, §2) in `GET /up`, in the login response and in `GET /me`. Binding: the session records the `apiBaseUrl` it was obtained from. On boot, if `API_BASE_URL === session.apiBaseUrl` the session is used; otherwise `initializeCloudAsync` first calls `GET /up` (unauthenticated) and uses the session only when the reported `serverId` matches, rebinding `apiBaseUrl`, else it drops it (the library stays; `needsReauth`). So a token never goes to a base URL that hasn't proven it is the session's server, and a new dev tunnel host doesn't cost a login. Offline on boot with a changed base URL means `needsReauth` until online; a production build's base URL never changes.

### 1.4 Opening, closing, switching

Boot (`AppInit`, which moves above the gate and no longer needs the database): read the registry (running `migrateInstall` once if there is none) and the session, both local and fast, and decide the library to open without the network: the session's owner's library if there is a session (created if missing, which is how a session written by the web preview gets its library), else `registry.openId`, else the device library. `LibraryGate` opens it at once while `initializeCloudAsync` verifies the session concurrently (`/up` when the base URL changed, `/me` when the session has no email or `serverId`); `isAuthenticated` turns true only when that passes, and sync starts only then, so no token is sent before the server is known and the open library needs no switch whatever the outcome (a dropped session makes it `needsReauth`). That also closes the "Start cloud init while the database opens" todo.

`LibraryGate` (replaces `DatabaseGate` + `MigrationGate`): holds `library` and `next` state; `switchLibrary(id)` sets `next`, the gate renders `null` while `next` is set, so every consumer below unmounts and its effect cleanup runs (`watchQuery.stop()`, the thumbnail loader's refs, the backup run's abort), and an effect of the gate, after that commit, performs the switch and then sets `library` and remounts the tree under `key={library.id}`; `switchLibrary(id)` resolves once the new library is open, so `CloudProvider` sets `isAuthenticated` only after it. No live query, watch or handler can read the wrong database: nothing is mounted while the connection changes, and the new tree starts its reads on the new one. The switch itself runs inside `withSyncPaused` (waits for a running sync, holds new ones): abort the backup run and wait for it; snapshot the closing library's `pendingCount` (outbox count), `unsyncedCount` (`readBackupCounts`) and `bytes` (`getInfoAsync(dir, { size: true })` of both folders; confirm on device that iOS returns a directory's total, else sum once); `closeDatabase()`; write the registry (`closed` snapshot, `openId`, `lastOpenedAt`); clear `webThumbnailUrls`; `openDatabase(next.dbName)` and create its two folders. The session changes (sign-in, sign-out, expiry) go through the same `withSyncPaused` section, so a sync run never spans a session or library change, which is why only the backup run needs its own abort (§1.7). `setSyncActive(appIsReady && isAuthenticated)` keeps its one effect; `isAuthenticated` comes from a pure `sessionMatches(library, session)` (tested) and now means "an account library is open with its verified session".

### 1.5 The flows

- **(a) Session expired.** `onSessionExpired` sets the session to `null` (nothing else changes: the library stays open and editable, writes queue in its outbox as today) and alerts "Sign in to keep syncing" / "Your session for <email> ended. Your changes are saved on this iPhone and will upload after you sign in." / Not Now · Sign In (→ Settings). While `needsReauth`: Settings' Account section shows "Sign in to sync · N changes, M photos waiting" (N = `pendingCount`, M = `unsyncedCount`) above the `LoginForm` with the owner's email pre-filled and read-only; the Backup & Sync rows stay visible with their live counts (`useBackupCounts` drops its `isAuthenticated` gate: counts belong to the library, the run needs the session); the header avatar (`FloatingHeader`) shows the needs-attention state. Re-signing in as the owner restores the session and sync pushes the outbox; signing in as someone else is (c).
- **(b) Explicit sign-out.** "Sign out" opens an action sheet (`ActionSheetProvider` is mounted; `Album.jsx` is the pattern) titled with the counts ("3 changes and 12 photos haven't synced yet" or "Everything is synced"), options "Keep on This iPhone" (default; the library is parked: `/auth/logout` revokes the refresh token, the session is cleared, the device library opens), "Remove from This iPhone" (destructive: if anything is unsynced, a second Alert "Remove 3 unsynced changes and 12 photos?"; then logout, switch to the device library, `removeLibrary(parked)`), Cancel. `confirmLogoutAsync` goes. The sheet is truthful at every step: in step 1, before libraries exist, the text already says "Your library stays on this iPhone."
- **(c) Sign-in as another account.** Login returns `{ serverId, user }`; `findAccountLibrary` → the parked library (its outbox pushes on the next sync) or a new empty one; A's library is parked untouched by the switch. `confirmLoginAsync` goes (there is nothing to warn about). Settings gets "Libraries on this iPhone": one row per library (label: email or the device label; value: "N pending · 1.2 GB" from the `closed` snapshot, live for the open one; "Open" marker on the open one), tap on a parked one → Alert with Remove (destructive, counted). The open library is removed only through (b).
- **(d) Backends.** §1.3 and §2. Two servers with the same user id are two libraries. The migrated library's `serverId` is null until the first `/me` or login for its `userId` resolves it (§1.6).
- **(f) A local-only user signs in to an existing account.** After the account library's first sync has drained (so duplicates can be seen), if the device library holds records and no answer was given for this sign-in, one Alert: "Add N photos and M albums from This iPhone to <email>?" / Keep Separate · Add to Account. Add runs `mergeLibrary(device → account)` behind the progress overlay (`useRunWithProgress`): source and target are both open (the target is the open db; the source is opened with `platform.openDb`, a second connection, 4 of web's 6 handles); records copy collection by collection in `APPLY_BATCH`-sized transactions through `saveRecords(…, { isNew: true })`, so each copied record gets its `nextVersion` and an outbox row like any local write, and live reads see them. Skipped: a record whose `id` already exists in the target (exact: the same record), an asset whose `mediaLibraryAssetId` exists live in the target (the id map then points edges at the existing asset), and edges whose asset or parent was skipped for being deleted; same-name albums are kept separate (two albums). Files move (`fs.move`, a rename on iOS) from the source folders to the target's as their asset copies; a file that is missing stays missing (the backup marks it as today). The source is only read until the copy and the moves are complete; then, per decision 5 (§6), the device library is emptied/removed. Keep Separate leaves it parked; it shows in "Libraries on this iPhone".
- **(g) A local-only user creates a new account.** There is no sign-up endpoint (accounts are seeded), so (g) is (f) against an empty account: the first sync pulls nothing, the dialog asks, Add copies everything; nothing is skipped. One code path; relabeling the device library in place would save the copy but adds a second path, and device-only libraries are small (phone-added photos). Revisit if a measurement says otherwise.
- **(h) Sign-out returns to the device library** (both sheet options), created empty if missing.

### 1.6 Migration of existing installs

`migrateInstall` runs when the registry is missing. It opens `squidbox.db` (which creates it on a fresh install: that is fine, the fresh install's device library is then `squidbox.db` too, and no "fresh" path exists), migrates it, reads `lastSyncUserId` and whether any collection has rows, and writes the first entry with `dbName: 'squidbox.db'`, `filesDir: 'assetfiles/'`, `thumbnailsDir: 'assetthumbnails/'`:

- `lastSyncUserId` set → owner `{ kind: 'account', serverId: null, userId, email }`, the email from the session (step 2 already turned the old token keys and the stored `user` into one session record with `serverId: null`) if its `userId` matches, else `''`; the first `/me` fills `serverId` and the email into both. A `/me` 401/403 clears the session (not the library): `needsReauth` with the email pre-filled, the data untouched.
- no `lastSyncUserId` → owner `{ kind: 'device' }`, with or without rows. This is the "unknown owner" case folded into the device library (§6, decision 4): (f)'s dialog resolves it at the next sign-in, and the merge's id check makes the one risky case safe: data that was in fact that account's (a build between `3f616f0` and `43c1bdf`, before `lastSyncUserId` existed) is skipped record by record because the account library already holds the same ids after its first pull.
- `lastSyncUserId` is left in `sync_meta` (unread; a later migration may drop it).

Nothing is moved, renamed or deleted, so a crash at any point re-runs the migration from the same state. Users lose nothing: the same database, the same folders, and a session that keeps working.

### 1.7 Phase-1 safeguards, under this model

- **Backup run** (`sync/backupRun.ts`, the loop out of `CloudSyncProvider`, which keeps the progress state): `runBackup(db, ids, { upload, isCurrent, onProgress })` captures `{ libraryId, userId }` at start through `isCurrent()` and stops before each asset, between an upload and its `updateAsset`/`deleteAssetFileAsync`, and before the thumbnail upload when the library or session changed, without `syncError` and without deleting the file; an upload in flight is cancelled (`uploadTask.cancelAsync()`, the TODO in `uploadFileAsync`). `uploadFileAsync(filename, uri, session, onProgress)` takes the session it must use; its 401 retry calls `refreshAccessTokenAsync(session)`, which refreshes only while the stored session is still that user's and otherwise throws `SessionChanged`. `apiWithAuthentication` does the same: the request interceptor notes the session on the config, the response interceptor refreshes against it. "Never refresh into a different user" is then one check in one place.
- **`logoutAsync`** posts `/auth/logout` through plain `api` with the session's refresh token (the route needs no auth, §0), then clears the session; a failed request still clears it (as today).
- **`initializeCloudAsync`** clears the session only on a 401/403 from `/me` (or `/up` reporting another server, §1.3); a network error keeps it and the app boots `isAuthenticated` from the stored email, as a production build does today when `user` is stored.
- **`refreshAccessTokenAsync`** writes the session once (both tokens) and keeps today's single-flight and "a newer sign-in replaced the session" guard, now by `userId` + `refreshToken`.
- **Server** (§2): refresh-token grace, `authenticate` rejects unknown users.
- **Counts stay visible while `needsReauth`** (§1.5 (a)); **sign-out text is truthful** ((b)); **orphaned files** are gone because files live in the library's folders and leave with it.

### 1.8 Web

Same code: expo-sqlite named databases on both platforms, one open at a time (`closeAsync` before `openDatabaseAsync`, never two handles on one name, §0), two during a merge. The registry and session use AsyncStorage/localStorage as today. The file helpers aren't called on web (`webThumbnailUrls` stands in, cleared on a switch). `scripts/webPreview.mjs` writes the session record (`serverId` from the login response, `apiBaseUrl: API_URL`) instead of the two keys; boot then creates the account library and syncs it, as a restored session does on a device (§1.4), so `openWebPreview()` and `settleAsync` keep working unchanged for every existing script. Each preview run is a fresh browser context (new OPFS), so the migration path with an empty state runs on every preview: a device library, then the account library.

## 2. Server

- `SERVER_ID`: a uuid in `config.ts` (required; `.env.docker` gets a fixed one for `dev:local`; a Fly secret in production, set by `/deploy-server` before the next deploy). Reported by `GET /up` (`{ status, serverId }`), `POST /auth/login` (`{ …, serverId }`) and `GET /me` (`{ user, serverId }`); the shared contracts (`packages/shared/contracts/auth.ts`) add the field. The app ignores unknown fields, so the server ships first (the rule from sync-design §6).
- `authenticate` loads the user (`findUserById`) and throws `AppError.unauthorized` when missing; `storageFor` keeps its lookup for the storage location. One query per authenticated request, on routes that already hit the database.
- Refresh-token grace: `refresh_tokens` gains `replaced_by text` and `replaced_at timestamptz` (migration 0005). `rotateRefreshToken` marks the presented row instead of deleting it and inserts its successor; presenting a row replaced less than 60 s ago returns the same successor (and a freshly signed access token); older → 401. The rotation deletes rows replaced more than 60 s ago (one `DELETE … WHERE replaced_at < now - 60s` per rotate, no job). `revokeRefreshToken` deletes the presented token and any row it replaced or that replaced it (`token = ? OR replaced_by = ?` plus the successor named by its own `replaced_by`). Tests in `tokens.test.ts` (fake db, as today) and `routes.auth.test.ts`.

## 6. Open decisions (recommendation first)

1. **Is the device library visible to a signed-in user?** Recommend: listed in "Libraries on this iPhone" only when it holds records, with its counts and size, not openable from there (§4). Alternative: always listed.
2. **The device label.** Recommend `libraryLabel`: "This iPhone" on iOS phones, "This iPad" on pads (`Platform.isPad`), "This device" on web. Alternative: "This device" everywhere.
3. **What Settings shows when signed out.** Recommend: the login form under "Account", the Libraries section (parked libraries, and the device library per decision 1), the AI and Data sections as today, Backup & Sync hidden (the device library has nothing to sync). Alternative: show Backup & Sync greyed with "Sign in to back up".
4. **"Unknown owner".** Recommend folding it into the device library (§1.6): one owner kind less, the merge's id check covers the risky case. Alternative: a third owner kind with its own label, resolved by a dedicated "Is this <email>'s library?" dialog.
5. **When the device library is emptied after Add to Account.** The investigation says only after push and backup complete. Recommend removing it as soon as the copy and the file moves have completed: the records are then durably in the account library's outbox and the files in its folders, exactly where a locally added photo lives before its upload, and the account library's own counts show what is left to push and back up. Keeping the source until backup completes adds a `merging` state to the registry, and backup is manual, so that state can linger for weeks. Both are a few lines; the choice is about the UI promise.
6. **Keep Separate: remember it?** Recommend asking once per sign-in into that account (no persisted flag); a later merge from the Libraries list is §4. Alternative: persist `keepSeparateFrom` on the device library.
7. **One session or one per library.** Recommend one (§1.3): signing back into a parked library asks for the password. Alternative: keep each library's refresh token so switching accounts is a tap; more state to keep valid and to revoke.
8. **Where the reauth marker lives.** Recommend the Settings row plus the header avatar state. Alternative: a banner on every screen.
9. **`SERVER_ID` source.** Recommend the env/secret (§2). Alternative: a `server_settings` row generated at migrate; it survives a lost secret but adds a table.
10. **Directory size in the Libraries list.** Recommend showing it only if `getInfoAsync(dir, { size: true })` measures fast at 10k files on device (step 4); otherwise show counts only.

## 7. Risks and checks

- **Web OPFS handles.** One open database costs two of the pool's six; a merge opens a second one (four). SQLite temp files during the big `INSERT` batches may need more: check in step 6's web run; if the pool overflows, the merge on web copies through the open connection with `ATTACH DATABASE` (the name is the VFS path on web; `defaultDatabaseDirectory/name` on iOS), which needs no second handle.
- **Closing under load.** A read already in the driver queue when `close()` is queued still runs before it (the queue is FIFO), so nothing reads a closed connection; a statement queued after it rejects, which a stopped watch only logs (`watchQuery` catches). `driver.test` pins both.
- **Shared native handles.** Both platforms share one handle per name: the library module is the only opener, and it never opens a name it hasn't closed (the merge opens a *different* name). iOS `deleteDatabaseAsync` throws while a database is open and when the file is missing: `removeLibrary` closes first and tolerates a missing file.
- **The install migration on the owner's phone** runs once and moves nothing; a device check before the build goes out (step 4). The `/me` that resolves `serverId` can fail offline: the library then waits with `serverId: null`, and sync is gated on `isAuthenticated`, which the session's `serverId: null` satisfies only against the migrated library (the only one with a null); `findAccountLibrary(serverId, userId)` treats a null in the library as a match for its `userId` until resolved.
- **Backup abort granularity.** An upload in flight is cancelled; the server may still complete a multipart upload it had already received. The file then exists in A's storage with the record not marked, and the next run uploads it again to the same key: harmless (sync-design §4's argument).
- **Sessions bound to the base URL** cost one `/up` per changed dev tunnel; a production build never pays it.
- **A refresh race across the 60 s grace** returns the same successor to both callers, by design; after the grace the old token is gone as today.
- **`FirstSyncScreen` under `needsReauth`**: a library whose first sync never drained and whose session expired shows the app empty with the marker rather than the setup screen; acceptable (step 5's rule), and re-signing in resumes the pull.
- **Measurements**: a switch (close + open + migrate of an already-migrated db) should stay under 300 ms on device and 1 s on web; `removeLibrary` of 10k files runs behind the overlay; the merge copies at `saveRecords` speed (a few statements per 500 records, sync-design §8). Record them in the todo's device-check entry.
